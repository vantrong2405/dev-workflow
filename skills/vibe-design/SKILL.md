# Design Vibe screens

Use `references/vibe-design.md` and `templates/vibe/design.md`. Work from the business
flows and acceptance criteria already gathered by Vibe.

1. Identify who uses the screen, the action they need to finish, the data they scan, and
   the states the interface needs to communicate. Find existing project brand tokens and
   design assets first. For a new direction, inspect a credible reference for a similar
   product or screen and a published source for the palette.
2. Compare the reference with this screen. Record what transfers and why. Choose a single
   visual direction, a display hierarchy, one primary action per screen, and semantic roles
   for color. Keep the brand and interaction conventions the user has already chosen.
3. Map the references and decisions to the Vibe input: theme, color overrides if needed,
   template, viewport, states and controls. Give Vibe the design record and source links.
   When the renderer returns, check the browser output for hierarchy, contrast, responsive
   layout and readable form errors. Add the checks and image revision to the same record.

Resolve ordinary design choices yourself using the project and reference material. Ask when a
missing answer changes a business behavior, or when two conflicting brand requirements cannot
both be met. Reuse an existing design record when the relevant choices still apply.
